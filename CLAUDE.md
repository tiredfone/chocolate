# Chocolate

Browser port of the 2012 client, version 26.11.3-hotfix (year, month, release; bump `package.json`, `package-lock.json`, the default `userAgent` in `config.php` and the server fallbacks together). Read `README.md` for the layout, configuration, endpoint contracts and join flow. This folder is served live, so a saved edit to `client/` or `shared/` reaches players on their next page load.

## Code style

- No comments in JS, Lua, PHP, CSS or HTML. Do not add section headers, inline explanations or docblocks.
- ES modules only. Keep the client free of a build step: browser code imports by relative path or through the import map.

## Rules

- **CoreScripts are run exactly as given.** Never edit a CoreScript, add a client-side alias for one, or skip one. When a CoreScript fails, implement the engine behaviour it expects. The only alias allowed is `CORE_ALIASES` in `client/assets.js`, for IDs the StarterScript references that have no file.
- **Nothing connects to a particular website directly.** Every host URL, path, port, file location and secret comes from `config.php` merged with `config.local.php`. On the server, read it through `server/config.js` (`config`, `endpoint`, `siteUrl`). In the browser, use `endpointUrl` and `publicPath` from `client/assets.js`, which get their values from the page's `#chocolate-config`. Do not hard-code `/api/...`, `/Asset`, `/game/...` or a site domain, and do not read the host site's files or config.
- **Secrets stay server-side.** `key`, `siteUrl` and `assetDir` must never reach the page or a log line. `config.local.php` is gitignored; stage files by name.
- **Visuals come from `content/`.** Use the client's own textures, sky, sprites, 9-slice images and sounds through `contentUrl`, `contentTexture` and `nineSlice`. Procedural textures are only fallbacks for files the content folder lacks. Files the desktop content lacks come from the matching iOS app (ROBLOX 2.4.1 IPA): `client/ui/TouchControlsSheet.png` is its `thumbstickOuter`, `thumbstickInner`, `jumpButtonPress` and `jumpbutton` at the sheet rectangles TouchControls uses, and `client/ui/roblox-logo.png` is its `roblox-logo@2x.png`. IPA PNGs are Apple CgBI files; `tools/ipa-ui.mjs` converts them and builds `client/ui/`. Map such files in `LOCAL_CONTENT`. Neither `content/` nor `client/ui/*.png` is committed: they are Roblox's files.
- **Characters get the client's own scripts.** The server inserts `Animate` and `RobloxTeam` from `content/fonts/humanoidAnimateLocal.rbxm`, `Sound` from `humanoidSound.rbxm` and `Health` from `humanoidHealth.rbxm`, as the 2012 engine did, and fires Humanoid `Running`, `Jumping`, `FreeFalling` and `Climbing` from client state updates. The JS animation in `shared/humanoid.js` only runs for characters whose `Animate` LocalScript is not running locally.
- **Touch mode loads the Settings CoreScript.** The StarterScript skips Settings on touch devices, which left no menu in a browser. The engine adds Settings (46295863) at the moment the StarterScript adds TouchControls and keeps `BottomLeftControl` visible for its button. There is no HTML menu.
- **Engine-built GUI lives in `client/world.js`.** The 2012 engine made `RobloxGui.ControlFrame` and its controls itself; CoreScripts wait for those objects by name. Keep their names and parents. Desktop gets the small camera cluster bottom right and no background plates; touch devices get no camera cluster and the iOS app's Leave button and leave menu (`LeaveMenu*` images from the IPA).
- **CoreScript names are kept exactly.** `AddCoreScript(id, parent, name)` names the script `name` as given, path included; other scripts wait for names such as `CoreScripts/BackpackScripts/BackpackManager`.
- **The GUI has a minimum resolution.** `ClientWorld.guiScale()` makes the CoreScripts see at least 640 units on the short side (the iOS app's 960x640) and the page scales the GUI layer down to fit with CSS `zoom`. Touch coordinates, `Mouse.X/Y` and `GetScreenResolution` use the scaled units. `GuiService:SetGlobalGuiInset` reserves strips (ChatScript uses a 20px bottom strip for its bar).
- **The loading screen is the 2012 engine's.** `#chocolate-loading` shows the default sky (`sky/null_plainsky512_ft.jpg`) behind a translucent grey panel with Bricks (parts in Workspace) and Connectors (joints) counting up, then fades out (`finishLoading` in `client/main.js`). `NewLoadingScreen` is off, so the engine never adds the newer LoadingScript (158948138), as this 2012 build did not.
- **Hint and Message look like the 2012 engine:** a black top bar and a dimmed screen with white bold Arial.
- **Parts render like the 2012 OGRE client.** Every part, mesh, limb and decal uses `Material2012` from `client/shade2012.js`, which ports the client's own `shaders/materials` scripts: lighting in gamma space (no linear workflow, no MSAA), a sun lamp with specular, an opposite fill lamp and `Lighting.Ambient`, and modulative shadows tinted by `Lighting.ShadowColor`. Material textures are the medium-quality `*Fallback` files applied with `add_signed` and each script's texture transform (`MATERIALS`); surfaces come from `textures/surfacesAlpha.png`, alpha-blended over the lit colour on every material. Part geometry needs the `tpos` attribute (`texPosAttribute`). Lighting is clamped before material textures and studs, as D3D9 clamped vertex lighting before its texture stages; otherwise bright places (white `Ambient`) wash them out. A texture whose image arrives after the first frame must be `dispose()`d before `needsUpdate`, because WebGL2 textures keep the size of their first upload (see `contentTexture`). Do not add `MeshPhongMaterial` or other lit three.js materials for world geometry.
- **Studio keeps places lossless.** `studio/` edits a local DataModel loaded with `{ track: true }` and saves through `shared/rbxlx.js`. Never drop `fileProps`, `fileRef` or `extra` from loaded instances, and record every property Studio changes in `dirtyProps` (`Studio.setPropRaw`). Changes go through `Studio.record` so they can be undone. Studio's art comes from `RobloxApp.exe` via `tools/studio-ui.mjs`; `studio/ui/*.png` is not committed. Studio runs no Lua.
- **Team Create syncs through DataModel observers.** `studio/teamcreate.js` turns every `changed` and `reparented` into an operation, so any new Studio feature syncs as long as it changes instances through `dm.setProp` and `dm.setParent` (directly setting `props` on a parented instance is not seen). Deleting is a move to nil, never `dm.destroy`, so undo and other editors keep the instance. Instances are identified by `gid` (`shared/teamsync.js`), never by `id`, which differs per DataModel. `server/teamcreate.js` holds the authoritative copy and must stay lossless: run the round-trip described under Testing in `README.md` (pack, unpack, `writePlace` on both sides must be identical) after changing `teamsync.js` or `rbxlx.js`. Studio tickets are redeemed with `mode: studio` and never reach a game worker.
- **Studio's reference comes from the engine.** Autocomplete and the Object Browser (`studio/reference.js`, `studio/browser.js`) read classes from `shared/classes.js` and methods, computed properties and events from `memberIndex()` in `shared/luahost.js`, so anything added to the engine API shows up there without extra work. Lua libraries and datatype members are listed in `reference.js`.
- **Cursors are the client's own.** `client/cursor.js` resolves `rbxasset://` and asset-ID icons to a CSS cursor with the hotspot at the image centre, as 2012 drew them, and draws the same image as an overlay while the pointer is locked so right-drag camera turning never hides the cursor. The game uses `ArrowFarCursor`, `ArrowCursor`, `DragCursor` over ClickDetectors and `Mouse.Icon` (the held tool's mouse first); Studio's tools use their 2012 cursors in `StudioView.updateCursor`.
- **Characters are built the 2012 way.** R6 body parts use the client's meshes: `content/fonts/head.mesh` for Head-type SpecialMeshes (normalised to unit size, since builds ship it at different scales) and `torso.mesh`, `leftarm.mesh`, `rightarm.mesh`, `leftleg.mesh`, `rightleg.mesh` for the body; clothing is composited into a 1024x512 atlas with the `Composit*.mesh` files in the engine's order (body colours, pants, shirt, T-shirt) by `client/character2012.js`. Studs and inlets follow vanilla's 2012 renderer, not the part surfaces: studs on the tops of the torso and arms and inlets on the bottoms of the arms, both only when no Shirt is worn; legs and the torso bottom show their texture. When body colours change on a clothed character, the atlas is redrawn into the same render target, so every limb keeps a live texture.
- **Engine-drawn text uses the client's bitmap fonts.** Nametags (ArialBold-18pt, team colour) and chat bubbles (Arial-18pt on the `chatBubble_white` 9-slice, tail drawn into the same canvas) go through `client/bitmapfont.js`; do not switch them to CSS fonts.
- **Shadows follow 2012's stencil look:** faces turned away from the sun are fully tinted by `ShadowColor`, so the shadow map is only sampled on lit faces.
- **Match 2012 replication where scripts depend on it.** Place scripts run once before the first player joins, so `PlayerAdded` handlers are connected in time. The client fires `Player.CharacterAdded` and `CharacterRemoving` itself when `Character` changes (the LoadoutScript rebuilds the hotbar on it). A client's change to a Value object inside its own character, Backpack or PlayerGui is sent to the server (`val`), as 2012 did with FilteringEnabled off. So does lowering the player's own `Humanoid.Health` and `BreakJoints` on its own character's parts (`hp`, `break`), which LocalScript reset tools rely on; nothing else replicates from client to server. The server kills a character as soon as any joint in its rig is destroyed, however that happens. Numeric keys on instances (`model[1]`) are looked up as child names. On the server, `Players.LocalPlayer` read by a Script inside a player's Backpack, PlayerGui or character returns that player, so classic HopperBin and tool Scripts (such as Reset) work.
- **Animations play through `shared/animator.js`.** `Humanoid:LoadAnimation` returns an `AnimationTrack` instance; `Play`, `Stop`, `AdjustSpeed` and `AdjustWeight` go to `env.animate`, which runs the track in an `Animations` player on both client and server. The player loads the `KeyframeSequence` asset, blends Pose CFrames by track weight and fade, and sets each joint's `anim` field, keyed by the Pose name matching the joint's `Part1`; `Rig.pose` applies it after `C0` and the motor angle. Tracks a server Script plays are broadcast as `anim` messages and sent to players who join later; a client's tracks on its own character go to the server, which runs them (so hitboxes follow) and relays them to everyone else. `KeyframeReached` skips keyframes named `Keyframe`, as Roblox does.
- **Tools behave like 2012 gear expects.** `Tool.Equipped` and `HopperBin.Selected` get a fresh Mouse each time (`openToolMouse` on client and server); it receives events and position updates only while that tool is held, because old gear connects to it on every equip and never disconnects. `GripPos`, `GripForward`, `GripRight` and `GripUp` are views of `Grip`, and changing `Grip` while the tool is held updates the `RightGrip` weld (`syncGrip`). A Script with an empty `Source` and a `LinkedSource` URL runs that asset's text (`env.linkedSource`). An event queued before its script stopped is not delivered (`J.running`), so scripts in a removed tool do not run against a nil `Parent`.
- **A place can run several servers.** `server/main.js` keys servers by job id, not place id. `chooseInstance` puts a player in the busiest public server with room (or the one `serverKey` names) and starts a new one when all are full; private (`priv:`) and reserved (`res:`) servers have exactly one instance each. Every join, leave and shutdown calls `pushPresence()`, which sends the full list of who is playing or in Team Create to the site's `presence` endpoint. `/status` and `/shutdown` are local-only; `/shutdown` needs the shared key.
- **Character movement must survive overlapping geometry.** `Controller` lifts the character out of floors that spawn across its feet (`unstick`) and uses a normal nudge factor so coincident floors (two coplanar baseplates) do not trap it. `CharacterProxy` creates its body and limb sensors at the character's current pose; created at the origin, they fire `Touched` on whatever sits there (kill bricks broke every new character's joints). Re-run `tools/movement.mjs` after changing either.
- **Badges and friends go through the host's `social` endpoint** (`server/social.js`). `BadgeService:AwardBadge` and `UserHasBadge`, `Player:IsFriendsWith` and `GetFriendsOnline` run on the server through `env`. The server asks the host for each player's FriendStatus with everyone in the game when they join and pushes it to their client (`fs`), so `GetFriendStatus` answers synchronously on the client. `RequestFriendship` and `RevokeFriendship` from a client go to the server (`friend`, at most one per 1.5 seconds), which updates both players and sends `fre`; the client fires `Player.FriendStatusChanged` and `Players.FriendRequestEvent`. `GuiService:SendNotification(title, text, image, duration, callback)` runs in Lua (`runtime.lua`) and builds the 2012 notification in `RobloxGui`; tapping it runs the callback. Values crossing to Lua as key/value tables use `T.dict` (tag `d`).
- **Host perks arrive as `SolarPerks`.** When `redeem` answers `perks` (`badge` as an `/asset/?id=N` path, `chatColor`, `nameColor` as `#rrggbb`), `server/main.js` validates them and the server adds a `SolarPerks` Configuration to the Player before it enters Players (`Badge` StringValue, `ChatColor` and `NameColor` Color3Values). The host's own CoreScripts read it; the engine only uses `NameColor` for the nametag of a neutral player.
- **Characters do not spawn inside each other.** `spawnPoint` tries other spots on the SpawnLocation (or around the origin when there is none, raycasting past characters) for one with no character within 3 studs, and otherwise places the new character above them; two characters created in the same spot pushed one through thin floors.
- **A VehicleSeat drives the wheels hinged to its chassis.** While it has an Occupant and a Throttle or Steer, `driveVehicles` sets each hinge's motor so the wheel rolls along the seat's look vector at `MaxSpeed × clamp(Throttle ∓ Steer × TurnSpeed)` studs/s (left wheels add Steer, right wheels subtract it), with a gain from `Torque` and the wheel's mass; otherwise the hinges turn freely. A seated character's solid proxy is disabled (`CharacterProxy.setSeated`): as a kinematic body inside the car it shoved the wheels off and pushed cars through the floor. Re-check with a car place after touching hinges or motors.
- **Climbing ends with a hop.** `climbCheck` casts from the feet to above the head, and when a climb ends while the player still pushes the same way, the character gets enough upward speed to step onto a ledge up to about 3 studs above the truss.
- **Shift lock is the camera's.** Shift toggles `CameraController.shiftLock` (unless `StarterPlayer.EnableMouseLockOption` is false or the camera is Scriptable or Fixed). While the pointer is locked, the mouse turns the camera, the focus moves 1.75 studs to the right (less if a wall is there), the cursor is `MouseLockedCursor` at the centre, `Mouse.Hit` aims from the centre, and `Controller.update` turns the character to `input.face`. First person does the same without the offset.
- **Script output reaches the F9 console.** `client/devconsole.js` shows client output (from the `log` hook) and server output, which the server sends only to clients whose `redeem` said `dev`, starting with the last 200 lines. Do not send server output to other players.
- **Joints come from surfaces as in 2012.** Physics joins touching parts whose surfaces allow it (`canJoin`); Hinge, Motor and SteppingMotor surfaces join to any surface, and may sit inside the other part up to its thickness (`faceContact` with `deep`), as classic cars' wheels do. They are not welds: each side stays its own assembly, linked by a Rapier revolute joint about the hinge face's normal (`addHinge`, `syncHinges`), as are `Rotate`, `RotateP` and `RotateV` instances (axis: Part0 × C0's Z). Only one revolute joint links any two bodies, since a wheel touching its chassis in several places otherwise over-constrains the solver and explodes. A Humanoid model whose head is not linked to its torso by joints gets real `Weld`, `Glue` or `Snap` instances from its touching surfaces (`surfaceJoints`), because its rig is built from joint instances.

## 2018 client

A place's `ClientVersion` (2012 or 2018) comes from `redeem` as `clientVersion`. `server/main.js` only puts a player in an instance of the same era, and the server sends `era` in `init`, so the client boots in the server's era, not the page's. `dm.era` is 2018 on both sides of a 2018 game.

- Roblox's 2018 Core-Scripts (Apache 2.0, unmodified, `corescripts2018/`) run exactly as given; `node tools/core2018-bundle.mjs` rebuilds `corescripts2018/bundle.json`. `shared/core2018.js` builds `RobloxGui.Modules` (folders are Folders, `.lua` files ModuleScripts) and the default PlayerScripts. The server runs `ServerStarterScript`, which installs the 2018 chat.
- Classes, properties and enums come from the 0.349 API dump (`tools/api2018.mjs` writes `shared/classes2018.js`) and are merged into `classes.js` as a superset; `SKIP2018` lists members chocolate computes. 2018 engine methods are in `shared/api2018.js`; Lua-side ones (remotes, tweens, SetCore, BindToRenderStep, the 2018 ContextActionService) in `shared/runtime2018.lua`, loaded through `rt.extend` because `runtime.lua` is at its local limit. `LUA_CLASS` restricts each Lua-side method to its class.
- Linked properties (`Color` and `BrickColor`, `TextSize` and `FontSize`, `BodyColors` `*Color3`) stay in sync in `DataModel.setProp` through `linkProps`.
- Input reaches Lua as `UserInputService.__Input(io, processed, 'b'|'c'|'e')`; the 2018 ContextActionService sinks it before `InputBegan`/`InputChanged`/`InputEnded` fire. The ControlScript moves the character through `Player:Move` and `Humanoid.Jump`, and the CameraScript owns `Camera.CFrame` (`CameraController.luaDriven`).
- 2018 GUI: ScreenGuis start below the global GUI inset unless `IgnoreGuiInset`; the inset is what `GuiService:SetGlobalGuiInset` set (the LoadingScript sets 36 for the topbar), 36 until then, and it is applied once, not on top of a built-in offset. `AbsolutePosition`, `InputObject.Position` and touch coordinates exclude it.
- Place files' `FontFace` (modern font property) becomes the legacy `Font` when a place is parsed (`fillLegacyFonts` in `shared/rbxl.js`), keeping the raw XML `FontFace` so Studio saves stay lossless.
- The play page draws the 2018 loading screen itself for 2018 places (place thumbnail, name, creator, turning logo) so it shows from the first frame. In game, `Players:GetUserThumbnailAsync` and `AssetService:GetAssetThumbnailAsync` return the host's `thumbnail`, `avatarThumbnail` and `placeThumbnail` URLs, and `thumbnailSrc` in `client/gui.js` loads those URLs and Roblox's own thumbnail URLs in GUI images.
- Content: `rbxasset://` resolves into `content2018/` first (`node tools/content2018.mjs /path/to/2018-client`; DDS textures are converted to PNG), then `content/`.
- Verify with `node tools/corescripts2018.mjs desktop|touch`, `node tools/server2018.mjs <placeId> [2012|2018]` and `node tools/e2e2018.mjs <placeId>` (server and client together, including chat; `SECONDS`, `ALL=1` for all server output, `DUMP=Service,...` for the server's service children and `LUA='...'` for a client probe script). The one expected error is `PerformanceStatsManagerScript` setting `ZIndex = nil`, a bug in Roblox's own script.
- Script security follows 2018 identity rules, which anti-exploit scripts such as Adonis check. Game code cannot read or write `CoreGui` or anything under it, cannot set `RobloxLocked`, and `settings()` errors for it; in 2018 games `loadstring` errors on the client and on the server unless `ServerScriptService.LoadStringEnabled` is true. Game code is decided by the calling function's environment: one compiled from a game Script, LocalScript or game ModuleScript (`LuaMethods.__gameEnv`) is game code, one from a CoreScript or a module under CoreGui or RobloxReplicatedStorage (`__coreEnv`) is not, and any other environment (scripts' own `setfenv` tables) is decided by the thread's script (`__gameThread`). Runtime frames are skipped (`__gameCaller`). `getfenv` returns the script's environment for runtime-internal frames and level 0, as Lua 5.1 does for C functions. `pcall` calls any callable value, including userdata with a locked metatable. `FindService` returns only services that already exist, never errors, and the client never has `ServerStorage` or `ServerScriptService`.
- Lua strings are bytes. A string that is not valid UTF-8 crosses the Lua/JavaScript bridge and the network as `sx` (hex) and is held in JavaScript with each invalid byte as a lone surrogate (U+DC80 + byte), so encrypted strings (Adonis's remote commands) arrive byte for byte.
- A destroyed instance stays a valid reference: it resolves through the host's `ghosts` when it crosses to Lua or arrives in a remote's arguments, as Roblox keeps references the server still holds.
- Signals and connections are userdata (`typeof` gives `RBXScriptSignal` and `RBXScriptConnection`), wrapping the internal tables in `Signal.__box`.
- A running script keeps running when it is parented to nil or destroys itself (`script:Destroy()` goes through `__DestroySelf`); it stops when disabled or destroyed by anything else.
- `require(assetId)` loads the asset with `InsertService:LoadAsset` and requires its `MainModule`. `Game.start` waits (at most 15 s) until no `LoadAsset` has been pending for 0.5 s before the first player joins, as Roblox's servers finish starting scripts before anyone connects.
- Each client has a `ServerReplicator` in `NetworkServer` whose `GetPlayer()` is that player. `JointsService` replicates. `Archivable` never replicates; clients keep their own value.
- Collision groups live in `Workspace.CollisionGroups` (`name^id^mask` entries joined by `\`, Roblox's own format) and `BasePart.CollisionGroupId`; `shared/collisiongroups.js` parses them, physics sets Rapier collision groups from them and the character controller's filter honours them.
- `game:BindToClose` callbacks run on shutdown: the worker fires `__Close` and waits 2.5 s before exiting.
- Tween methods take their callback in Lua and call it with `TweenStatus.Completed` or `Canceled`.

## Engine API

- Classes, properties and enums: `shared/classes.js`. Enum items keep their 2012 names, including ones with spaces such as `"Mouse Lock Switch"`. Give an enum property its enum type in `ENUM_PROPS`, or in `CLASS_ENUM_PROPS` when the type depends on the class.
- Events: `EVENTS` at the top of `shared/luahost.js`.
- Methods: `def(names, class, fn)` in `buildMethods` in `shared/luahost.js`. Return `null` for nothing, wrap typed values with `T`, and return a Promise for yielding methods listed in `ASYNC`.
- Methods that take Lua functions or tables must run in Lua: add them to `LuaMethods` in `shared/runtime.lua` and to `LUA_SIDE` (restricted to their class in `methodName`). `ContextActionService` is the example.
- `shared/runtime.lua` is at Lua 5.1's limit of 200 top-level locals. Put new top-level state in an existing table such as `CAS`, never in a new `local`.
- Side effects that need the browser go through the `env` object built in `ClientWorld.env()`, which forwards to hooks set in `client/main.js`.

## Lua 5.1 rules for scripts

- `string.split` does not exist; use `string.gmatch`.
- Yielding across `pcall` aborts the thread, so anything that yields, such as `LoadAsset`, must stay outside `pcall`.

## Verifying changes

- `node --check` every changed JS file. For `runtime.lua`, compile it through wasmoon as the tools do.
- Run the matching tool in `tools/` (see `README.md`). A change to the engine API or to `classes.js` needs `node tools/corescripts.mjs desktop` and `touch` to stay free of errors.
- Changes under `server/` or `shared/` take effect on the game server only after it restarts. The play page gives every `client/` and `shared/` module its own `?v=` (file mtime) through the import map, so browsers and the site's service worker pick up a saved change on the next page load. Fetch any other per-build file with `?v=` too.
- Only make read-only requests to the host site while testing. `tools/character.mjs` is read-only.

## Skills

- `engine-api`: make a CoreScript or game script work by adding the engine behaviour it expects.
- `character-appearance`: find out why a player's character, clothing, colours or gear differ from the site.
- `touch-controls`: work on mobile input, TouchControls, ContextActionTouch or the touch-only UI.
